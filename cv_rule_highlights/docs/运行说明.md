 `cv_rule_highlights` 运行与维护说明

## 1. 环境与输入

所有命令从仓库根目录执行。以下变量供全文示例共用：

```bash
cd /data/wangyt/basketball-action-analysis
HIGHLIGHTS_PYTHON=/data/wangyt/envs/rfdetr-gpu/bin/python
HIGHLIGHTS_CONFIG=cv_rule_highlights/config/actual_11_9_segment_1_no_training.yaml
HIGHLIGHTS_RUN=cv_rule_highlights/output/segment_1_delivery_new
export PYTHONDONTWRITEBYTECODE=1
"$HIGHLIGHTS_PYTHON" -m cv_rule_highlights --help
```

`HIGHLIGHTS_RUN` 应设成尚不存在的新目录。命令示例中的重建、预览、评估输出目录也应按次命名，保留旧结果。

规则处理依赖 `requirements.txt` 中的 NumPy、OpenCV、PyYAML；视频渲染需要系统 `ffmpeg`、`ffprobe`。只有上游推理及 ROI 球补检需要 RF-DETR 对应的 GPU 环境、权重和上游依赖。`pytest` 为单独的开发测试依赖。

### 输入如何进入系统

| 输入 | 用途 | 是否需要先跑上游 |
|---|---|---|
| `poses_3d.json` | 人物框、COCO 关键点、track/ReID、球观测和多视角数据 | 是，由 `perception` 推理生成，已有文件可复用 |
| 四路同步原视频 | 篮网/篮筐局部视觉分析、人物截图和最终剪辑 | 不需重新推理，但运行时需可读取视频 |
| 各视角篮筐坐标 | 判断球与篮筐的空间关系、裁剪 ROI | 当前来自配置中的人工复核结果 |
| `perception_config` | 场地几何、上游推理或补检配置 | 配置文件需存在，读取几何本身不运行推理 |
| `rim_scan_cache` | 复用整段篮筐扫描证据 | 可选；缺失时读取视频扫描 |
| `ball_evidence` | 复用篮筐附近球补检证据 | 可选；缺失且启用扫描/补检时调用冻结模型补检 |

当前第一段自动配置引用以下已有文件，以及 `/data/tt/basketball/data/11.9/1视频/11.19/` 下的四路第一段视频：

```text
perception/output/actual_11_9/segment_1_full/poses/poses_3d.json
perception/config/actual_11_9/segment_1.yaml
cv_rule_highlights/output/segment1_20260923/roi/ball_evidence.jsonl
cv_rule_highlights/output/segment1_20260923/scan/summary.json
```

配置中的路径为本机绝对路径；迁移部署需要提供相应资源并调整路径，单独检出代码不能运行完整流程。原始视频 `/data/tt` 只读。使用 `--reuse-perception` 时不改写上游结果；不带该参数且感知输入缺失时，程序可能在配置指定的上游输出目录生成新结果。

人工高光、人员照片和动作标签只能用于独立评估，不能作为检测答案输入。

### 两种配置不要混用

- 自动流程配置：包含 `schema_version`、`segments`、`rims`、`rules` 等；用于 `auto-run`、`auto-plan` 和篮筐复核入口。当前使用 `actual_11_9_segment_1_no_training.yaml`。
- 单场景 Game 配置：包含 `poses`、`views`、`rules` 等；用于 `detect`、`run`、`preview`、`visualize`。自动流程会生成 `inputs/segment_1.yaml`，可直接用于这些命令。

## 2. 完整流程与视频生成

### 完整运行

```bash
"$HIGHLIGHTS_PYTHON" -m cv_rule_highlights auto-run \
  --config "$HIGHLIGHTS_CONFIG" --output "$HIGHLIGHTS_RUN" \
  --segments segment_1 --reuse-perception
```

流程依次读取感知结果、生成匿名身份、读取或计算篮筐和球证据、计算控球及队伍关系、生成事件账本，再输出统计、剪辑计划、视频、报告与审计。队伍关系利用整段自动事件推断；这里是离线处理流程。

`--reuse-perception` 的准确含义是：配置要求的感知文件缺失时，该段报错，禁止调用上游全流程；不是关闭所有 GPU 操作的总开关。篮筐扫描缓存不存在时仍会扫描视频；未配置球证据时仍可能进行 ROI 模型补检。已有有效缓存会自动复用，即使不带此参数也不会强制重新推理。

本次只处理 `segment_1`。第二、三段不在当前回归范围内。

### 只生成事件、统计和剪辑计划

在新目录运行同一命令，加 `--skip-render`：

```bash
"$HIGHLIGHTS_PYTHON" -m cv_rule_highlights auto-run \
  --config "$HIGHLIGHTS_CONFIG" --output "$HIGHLIGHTS_RUN" \
  --segments segment_1 --reuse-perception --skip-render
```

该命令仍生成全局、个人、分类和候选 EDL（剪辑决策清单），不生成 MP4。运行清单的总状态为 `partial`，其中 `render` 为 `skipped_by_request`，这是主动跳过渲染的预期结果。

`--skip-rim-scan`、`--skip-roi-redetect` 用于诊断，会减少检测证据，不能视为与完整流程等效。

### 从已有计划渲染视频

`render` 只读取 EDL 和源视频，不重新检测。全局、个人、分类视频使用相同入口，选取对应的 EDL 即可。下面以全局和进球分类为例：

```bash
"$HIGHLIGHTS_PYTHON" -m cv_rule_highlights render \
  --plan "$HIGHLIGHTS_RUN/confirmed/global/edit_decision_list.json" \
  --output "$HIGHLIGHTS_RUN/rendered_global"

"$HIGHLIGHTS_PYTHON" -m cv_rule_highlights render \
  --plan "$HIGHLIGHTS_RUN/confirmed/event_types/made/edit_decision_list.json" \
  --output "$HIGHLIGHTS_RUN/rendered_made"
```

个人视频把 `--plan` 改为 `confirmed/players/anon_0001/edit_decision_list.json` 等，并指定另一个新输出目录。默认尺寸为 1280×720，可用 `--size 1920 1080` 更改。渲染结果在新目录中的 `highlights.mp4`；没有合格片段的空计划不产生合集视频。

### 为旧运行补充事件分类输出

```bash
"$HIGHLIGHTS_PYTHON" -m cv_rule_highlights event-clips --run "$HIGHLIGHTS_RUN"
```

这个命令只适用于**尚不存在 `confirmed/event_types/` 的旧运行**。需保留完整运行目录，包括 `inputs/`、事件、身份、全局/个人/候选 EDL 和 `stats/players/`；仅复制事件账本并不足以重建报告。当前 `auto-run` 已经生成该目录，即使使用 `--skip-render` 也会生成分类计划，因此不能再直接运行此命令覆盖它。已有分类 EDL 应使用上一节的 `render` 导出到新目录。

## 3. 独立重算、复核与评估

### 重算统计

```bash
"$HIGHLIGHTS_PYTHON" -m cv_rule_highlights auto-stats \
  --events "$HIGHLIGHTS_RUN/events/all_events.json" \
  --players "$HIGHLIGHTS_RUN/identity/players.json" \
  --output "$HIGHLIGHTS_RUN/stats_rebuilt"
```

只读取事件账本和身份表，不使用 GPU，不修改原账本。结果为全局/个人 JSON、CSV 和个人 Markdown。

### 重建全局剪辑计划

```bash
"$HIGHLIGHTS_PYTHON" -m cv_rule_highlights auto-plan \
  --config "$HIGHLIGHTS_CONFIG" \
  --events "$HIGHLIGHTS_RUN/events/all_events.json" \
  --output "$HIGHLIGHTS_RUN/global_replanned"
```

生成 `global_replanned/edit_decision_list.json`，可交给 `render`。该命令读取感知缓存以重建控球边界及镜头评分，不运行 GPU 推理；只重建全局计划，个人/分类计划由 `auto-run` 生成。

### 查看篮筐标定

```bash
"$HIGHLIGHTS_PYTHON" -m cv_rule_highlights.rim_audit \
  --config "$HIGHLIGHTS_CONFIG" \
  --output "$HIGHLIGHTS_RUN/rim_audit"
```

读取配置中各段首帧、中间帧、末帧，生成四视角篮筐裁剪拼图；不自动修改标定。可加 `--events "$HIGHLIGHTS_RUN/events/all_events.json"` 查看已确认进球附近的拼图。该入口处理配置内的所有段，当前应使用第一段专用配置。

### 预览、球轨迹诊断和早期投篮流程

以下入口使用 Game 配置，不要传自动配置：

```bash
"$HIGHLIGHTS_PYTHON" -m cv_rule_highlights preview \
  --config "$HIGHLIGHTS_RUN/inputs/segment_1.yaml" \
  --output "$HIGHLIGHTS_RUN/preview" --frame 0

"$HIGHLIGHTS_PYTHON" -m cv_rule_highlights visualize \
  --config "$HIGHLIGHTS_RUN/inputs/segment_1.yaml" \
  --output "$HIGHLIGHTS_RUN/diagnostic" --view view1 --scale 0.5

"$HIGHLIGHTS_PYTHON" -m cv_rule_highlights detect \
  --config "$HIGHLIGHTS_RUN/inputs/segment_1.yaml" \
  --output "$HIGHLIGHTS_RUN/shots_only"
```

`preview` 导出配置预览图；`visualize` 绘制球轨迹与篮筐诊断视频；`detect` 生成早期投篮报告和剪辑计划。将 `detect` 换成 `run` 会同时渲染视频；`--review` 可纳入投失和未决候选。完整的多事件和个人输出应使用 `auto-run`。

### 独立评估

```bash
"$HIGHLIGHTS_PYTHON" -m cv_rule_highlights.evaluate_annotations \
  --annotations /data/tt/basketball/data/11.9/2高光时刻/1-3v3.json \
  --events "$HIGHLIGHTS_RUN/events/all_events.json" \
  --output "$HIGHLIGHTS_RUN/annotation_evaluation.json"
```

评估不会参与生产检测或修改事件账本。当前人工文件属于精选高光，不能默认覆盖全部真实事件。Recall 反映已有标注的检出情况；Precision/F1 若采用“标注穷举”假设，必须注明该假设。时间区间匹配也不能替代逐条人工核验。本次结构整理没有改变评估算法。

## 4. 输出位置和统计口径

```text
output/运行目录/
├── run_manifest.json                  # 输入、配置/代码摘要、阶段状态
├── quality_report.json                # 审计结果
├── inputs/segment_1.yaml               # 固化的 Game 配置
├── events/                            # 全量、分段和未决事件账本
├── identity/                          # 匿名人物、track 映射、队伍、头像
├── possession/                        # 控球段与控球状态
├── stats/                             # 全局/个人 JSON、CSV、Markdown
├── confirmed/
│   ├── global/                        # 全局 EDL 和视频
│   ├── players/匿名ID/                  # 个人 EDL 和视频
│   └── event_types/事件类型/            # 分类 EDL 和视频
├── candidates/                        # 候选合集计划和视频
├── review/                            # 篮板/抢断/盖帽逐条候选与计划
├── reports/                           # 总览、个人、分类及候选 HTML
└── ball_scans/                        # 本次计算的扫描或球补检；复用时可无
```

主要查看 `reports/index.html`、`reports/event_types.html` 和 `reports/candidate_review.html`。未渲染的计划运行可能还没有页面中对应的视频文件。

| 输出事件 | 当前含义 |
|---|---|
| `shot` / 分类目录 `made` | 投篮事件带命中结果；`made` 分类只导出符合条件的进球 |
| `rebound` | 投篮后的收球证据，包括进攻/防守篮板归属 |
| `successful_drive` | 控球、地面位置与防守关系支持的突破/过人 |
| `assist_chain` | 传球与后续命中关联的视觉助攻链，非官方助攻定义 |
| `steal`、`block` | 实验规则及核查候选；当前质量不足，暂不当作可信统计 |

底层视觉证据可能为 `unknown`。业务账本将已确认存在、过程完整但未确认命中的投篮按现有方案计为 `missed`；并非所有篮筐附近候选都直接记投失。统计按事件账本及人物角色归属计算，不能从视频片段数反推：相邻事件可能合并剪辑，同一事件也可能出现在多个角色的个人集锦中。实验抢断/盖帽仍可能出现在现有输出中，结构整理没有修改其规则或输出资格。

具体阈值、进球的多机位证据、每种动作规则和选镜头方法见[方法文档](../视觉规则篮球高光检测_方法功能效果与发展方向.md)。

## 5. 模块职责与维护

| 目录 | 主要文件与职责 |
|---|---|
| `src/core/` | `data.py`：Game、人物/球输入；`config.py`：自动配置与分段配置生成；`court.py`：场地几何；`timeline.py`：帧区间 |
| `src/perception/` | `detect.py`：投篮与篮筐穿越证据；`shot_evidence.py`：篮网证据；`ball_evidence.py`：篮筐扫描；`roi_redetect.py`：球补检；`rim_audit.py`、`visualize.py`：诊断 |
| `src/events/` | `event_rules.py`：共享规则；`auto_events.py`：事件账本；`possession.py`、`team.py`、`identity.py`：控球、队伍、身份 |
| `src/editing/` | `auto_clips.py`：高光计划；`shot_selection.py`：控球边界与镜头评分；`event_clips.py`、`candidate_review.py`：分类与核查；`clips.py`：FFmpeg 渲染 |
| `src/reporting/` | `stats.py`：统计；`reports.py`：报告；`audit.py`：审计与代码摘要；`evaluate_annotations.py`：离线评估 |
| `src/runners/` | `cli.py`：参数与命令分发；`auto_run.py`：阶段编排 |

入口只转发调用。共享配置放在 `core`，篮筐复核不再依赖整个运行流程。按“输入 → 视觉证据 → 事件 → 计划/统计 → 视频/报告”定位修改点，不在渲染代码中改变事件判断。

内部导入现在使用 `cv_rule_highlights.src.*`，例如：

```python
from cv_rule_highlights.src.core.data import Game
from cv_rule_highlights.src.events.auto_events import build_events
```

三个外部命令入口保持可用：`python -m cv_rule_highlights`、`python -m cv_rule_highlights.evaluate_annotations`、`python -m cv_rule_highlights.rim_audit`。本项目仍从仓库根目录运行，`src` 是包内实现目录；没有引入新的安装或打包步骤。

`run_manifest.json` 的代码摘要覆盖顶层入口和 `src` 下所有 Python 源码，排除输出、测试及文档。调整规则、标定或输入后，用新输出目录执行回归；不覆盖旧视频和账本。`output/`、Python 缓存及测试缓存不纳入 Git。

## 6. 验证与常见问题

```bash
"$HIGHLIGHTS_PYTHON" -m pytest cv_rule_highlights/tests -q \
  -o cache_dir=cv_rule_highlights/output/pytest_cache \
  --basetemp=cv_rule_highlights/output/pytest_tmp
```

运行后检查各阶段清单、审计报告、事件证据帧、统计守恒与输出视频。完整运行应为 `complete`；`--skip-render` 应为 `partial` 且渲染阶段明确跳过。`ffprobe` 用于查看视频信息，完整解码检查用：

```bash
ffmpeg -v error -i "$HIGHLIGHTS_RUN/confirmed/global/highlights.mp4" -f null -
```

| 现象 | 检查方法 |
|---|---|
| 输出目录已存在 | 使用新的运行目录，不覆盖旧结果；分类目录已存在时用 `render` |
| 感知输入缺失 | 检查配置绝对路径和缓存是否部署齐全；`--reuse-perception` 不负责补跑 |
| 篮筐扫描缓存标定/帧数不匹配 | 核对视频段、帧数和篮筐坐标；修正配置并在新运行中重新扫描 |
| 只看到 EDL，没有视频 | 检查是否用了 `--skip-render`，以及计划是否为空 |
| 个人或分类视频数量与事件数不同 | 检查角色归属、事件筛选与片段合并；视频不是统计单位 |
| 抢断/盖帽效果差 | 查看候选核查页，保留为实验结果，需独立改进规则和补齐标注 |
